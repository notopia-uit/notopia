## 1. Billing reliability and contracts

### Domain and transaction improvements

* Refactored billing domain models and value objects, including money, payment, price, subscription, and refund-related types. The changes clarify ownership and invariants and reduce accidental mutation. Further cleanup removed unused contact-update behavior. See [#365](https://github.com/notopia-uit/notopia/pull/365), `d78e47a3`, and `709bd76e`.
* Introduced a **transactional outbox**: billing database writes and outgoing events are persisted in the same transaction, then forwarded asynchronously. Provider cancellation and refund submission are driven by outbox events. This reduces the risk of a committed state change without a corresponding event; it does not remove the need for retries and idempotency. See `d78e47a3` and the [billing documentation](/services/billing/).
* Improved duplicate checkout handling under a workspace account lock and refund settlement handling, including not reopening settled refunds. Added or updated tests around billing domain behavior, provider interactions, and webhooks (`d78e47a3`).
* Made billing features and limits explicit types across the contract and dependent services, rather than relying solely on generic string keys (`f758ec9c`, `18cca64c`).
* Fixed Stripe customer-portal catalog configuration by specifying allowed update fields (`5196957d`), and improved sandbox customer descriptions (`775223ce`).

### API improvements

* Changed `GET /billing/workspaces/{workspaceId}/subscription` to `GET /billing/workspaces/{workspaceId}` because the response contains both subscription and payer, either of which may be null. Updated nullable response fields and required-field declarations (`a780d8bb`). This is a route change for API consumers.
* Expanded examples for plans, free workspace entitlements, and billing responses and clarified operation descriptions and webhook tagging (`ec85c290`, `a60d17ec`, `9e01d768`, `f6d2060c`, `2add6fca`).

## 3. API correctness and developer authentication

* In `234f7efa`, introduced separate creation request schemas for folders, notes, and workspaces instead of reusing full resource/response schemas. The latter include server-generated, read-only fields that may be required in responses but should not be required from clients. The note API was **already OpenAPI 3.1.2** before this commit; this was a contract correction for 3.1 validation, not an upgrade from 3.0 to 3.1 in this reporting range.
* OpenAPI 3.1 treats `readOnly` as a JSON Schema annotation and discusses applying `required` in the relevant request/response context; tooling can interpret this differently. Separate schemas make the input contract explicit and avoid relying on validator-specific behavior. Reference: [OpenAPI 3.1.2 Schema Object: `readOnly` and `writeOnly`](https://spec.openapis.org/oas/v3.1.2.html#extended-validation-with-readonly-and-writeonly).
* Enabled local Authentik fixture users and the API viewer client for password-grant testing (`a115e9d0`), complementing authorization-code and refresh-token configuration (`aba81097`). These fixture credentials and password grants are for local development; do not generalize them to production use.
* Expanded OAuth default scopes for API exploration (`17cc93ac`). Updated Redocly CLI to `2.82.0` (`2e80d890`); the update did not require application code changes.

## 4. Toolchains, dependencies, and build quality

* Split mise into shared, dev, and CI environments and added per-environment lockfiles (`711a6384`, `201943ad`). The split avoids installing local-only tools in CI and vice versa; locked versions, checksums, and dependency graphs support repeatable installations across machines. See [mise tooling](/developer/mise).
* Upgraded the gRPC/Protobuf toolchain ([#391](https://github.com/notopia-uit/notopia/pull/391), `93c0910c`): Buf `1.65.0 → 1.75.0`, ts-proto `2.12.4 → 2.22.0`, Go gRPC `1.84.0 → 1.85.0`, `@bufbuild/protobuf` `2.11.0 → 2.17.0`, protobufjs `8.4 → 8.8`, and related validation dependencies. Regenerated TypeScript protobuf output and made proto lint cache sensitive to Buf upgrades. Later updated Go protovalidate to `1.4.1` (`a349cfe8`).
* Removed `apps/document/inquire-shim.js`, not a generated proto stub ([#392](https://github.com/notopia-uit/notopia/pull/392), `eabfdb45`). It had worked around protobufjs dynamic module loading in Rspack; the replacement no longer matched a dependency, and the service uses generated ts-proto package definitions instead of loading `.proto` files at runtime. The recorded investigation found byte-identical application bundles with and without the shim. See [the bundling investigation](/developer/story/nestjs-bundling-otel) and [gRPC proto-loader investigation](/developer/story/nestjs-grpc-proto-loader).
* Other notable updates include Node 26, Go 1.27.4, Nx 24.0.6, NestJS 11.2.11, TypeORM 1.1.3, Next.js 16.4.6, Vitest 5.1.1, Rspack 2.3.3, oapi-codegen 2.9.0, and OpenAPI Generator CLI 2.42.2. Infrastructure updates included PostgreSQL 18.7, Meilisearch 1.57, Grafana 13.3.1, Tempo 3, and updated Authentik, Redpanda, and RustFS images. These are selected examples, not an exhaustive dependency inventory.
* Aligned Go and Node OpenTelemetry dependencies ([#380](https://github.com/notopia-uit/notopia/pull/380)); pinned `cron` to `4.4.0` for compatibility with `@nestjs/schedule` (`0a59ca58`). Enabled type-aware Oxlint and fixed identified issues (`891cecbe`, `00cd90e2`).

1. Finish RustFS and other homelab inputs, deploy the prepared releases, and run live security, startup, upgrade, and application-flow checks.
2. Resume prioritized billing UAT and add suitable automated integration coverage for duplicate charges, authorization, and webhook recovery. Resolve the logging and token/session security follow-up.
3. **NestJS 12:** wait for a compatible stable Nx release and confirm its Nest peer ranges before upgrading. The 2026-11-21 plan records upstream Nx support merged, but not yet available in the stable release used at that snapshot. [#350](https://github.com/notopia-uit/notopia/pull/350) covers the Nest upgrade; [#396](https://github.com/notopia-uit/notopia/pull/396) is a Terminus maintenance update, not the core blocker. The plan identified a search-worker Kafka mock requiring adaptation because Nest 12 makes `createClient` asynchronous; this was a migration finding, not a completed fix.
4. **Native ESM:** evaluate separately for document, AI, and search-worker. OpenTelemetry does not categorically prohibit ESM, but instrumentation must start before application imports and may require an ESM loader hook; Nest-specific instrumentation also has its own version-support limit. Align build output, telemetry preload, Docker and Kubernetes commands, migration/seed entrypoints, and verify actual logs, traces, startup, and shutdown. BlockNote compatibility is related but does not inherently block ESM or require an ESM application bundle. This is a plan, not an implemented migration. Source: `docs/superpowers/plans/2026-11-21-nestjs-12-native-esm-migration.md` (`7374de9f`).
5. **TypeORM extension:** consider [#346](https://github.com/notopia-uit/notopia/pull/346), including CLI and fixture validation. The plan records that extension 3.9.0 has an older TypeORM peer range while the project already resolves TypeORM 1.1.3.
