# Kubernetes CI and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify chart changes and manually release all six service images with Flux deployment tag updates.

**Architecture:** Reuse setup through a composite action while keeping the existing main and docs jobs. Check chart version changes against the Nx base, resolve one explicit image project list, release images and commit only selected cluster tag changes.

**Tech Stack:** GitHub Actions, Nx, Docker, mise, Helm, yq, Renovate.

**Spec:** `docs/superpowers/specs/2026-10-24-k8s-04-ci-release-design.md` and `docs/superpowers/specs/2026-10-24-k8s-00-overview-design.md`. Can proceed alongside plan 02; deployment tag integration requires plan 03 values files.

**Execution update (2026-11-14):** Implemented on `kevinntro/k8s-ci-release`. Per user direction, test-file/TDD steps were replaced by actionlint, ShellCheck, targeted local Git dry-runs and independent AI review. No images were published and no shared branches were pushed. The Nx billing release dry-run resolves only billing but stops at `docker tag` because no Docker daemon is available; tag-update and push-safety dry-runs use isolated local repositories instead. Renovate validation passes with a local native RE2 fallback warning.

**Release finalization and recovery:** Docker GitHub-release creation is disabled in Nx because its combined command announces before publishing images. Nx now creates local tags and publishes the selected images; only after all publishes succeed does the workflow atomically push the selected release tags and deployment commit, then create GitHub releases with generated notes. NPM keeps its existing Nx release behavior. If publishing or the atomic push fails, no Docker release tags or announcements are pushed by this invocation: rerun the same selection from the latest `main` to mint fresh versions; unreferenced images from a partial publish must not be deployed manually. If GitHub-release creation fails after the atomic push, images and deployment tags already exist; create only the missing announcements with `gh release create '<project>@<version>' --verify-tag --generate-notes`, using the exact tags from the successful push log rather than rerunning image publishing.

## Global Constraints

- Release remains manual and main-only; never push a deployment commit from a test branch.
- Keep Nx release tag pattern `{projectName}@{version}` and production/development schemes unchanged.
- `main` retains existing write permissions as explicitly accepted by spec; fork PR token remains read-only.
- Do not introduce Flux image automation; release owns Notopia tags, Renovate owns third-party versions.
- Match chart tools pinned in plan 02; install helm-unittest 1.2.1 and yq 4.54.1 in CI.

## Review Focus

- Common chart change must demand a higher version for every dependent (Task 2).
- New charts or deleted charts and invalid/missing base SHAs must not silently pass (Task 2).
- NPM-only dispatch must not accidentally build/release all Docker images (Task 3).
- Multiple tags at HEAD, no selected projects, missing values, or main advancing must not deploy wrong versions (Task 3).
- Docs-only changes must retain actual docs job behavior and composite setup (Task 1).
