Billing Service ​

Plans, prices, subscriptions and entitlements. Stripe (sandbox) through hosted Checkout and Customer Portal. DDD + CQRS like the Note service, with a Watermill transactional outbox: domain writes and event publishes commit together. Other services read entitlements over gRPC and never cache them.

  • Domain: class diagrams
  • Data: database diagram
  • Flows: checkout, webhooks, cancellation, crons

Architecture ​

Events ​

Repo Save writes the aggregate's popped domain events into outbox_messages in the same transaction. outbox.Forwarder relays them to Kafka, keyed by the aggregate id (workspace id for the integration event). Topics are declared once in internal/billing/component/eventtopic.go.

Published ​

TopicPayloadWhen
events.integration.billing.subscription.changed{workspaceId, plan, status}SubscriptionStateChangedEvent: recorded whenever a subscription's plan or status changes (not for duplicate checkouts)
events.internal.billing.{aggregate}.{event}the domain eventevery other domain event, e.g. subscription.canceled_now, subscription.refund_requested, billing_account.payer_missing, price.created, plan.updated

The events.internal.* topics are billing's own: only billing consumes them (see below).

Consumed ​

TopicUse case
events.integration.note.workspace.deletedHandleWorkspaceDeleted
events.integration.authorization.user_workspace_role_updatedHandlePayerRemoved (payer no longer owner)
events.integration.authorization.workspace_member_removedHandlePayerRemoved
events.internal.billing.subscription.canceled_nowCancelProviderSubscription (cancel at the provider)
events.internal.billing.subscription.refund_requestedSubmitRefund (create the provider refund)

One consumer group per topic. An undecodable payload or a permanent error (notFound, invalid) is logged and acked; other errors are retried.
